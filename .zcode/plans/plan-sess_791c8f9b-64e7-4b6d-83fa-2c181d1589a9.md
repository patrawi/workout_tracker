# Plan: Before-photo support in measured mode + pending-UI discoverability

## Context (what I found)

- **The pending-meal resolution UI already exists**: `PendingMeals` card on `/nutrition` (frontend/src/pages/NutritionPage.tsx:565) → click a row → `PendingMealDialog` (frontend/src/components/PendingMealDialog.tsx) with reference search → resolve → confirm. It only renders when the pending list is non-empty, and rows may not read as clickable — likely why it seemed missing.
- **Estimated mode already requires a before photo** and sends it to `/meal-observations/interpret` (DeepSeek VLM, `LogMealModal.tsx:243`).
- **Measured mode has no photo at all** (`LogMealModal.tsx:216-228` creates directly, no images) — this is the gap.
- Images are **never persisted** anywhere: `/interpret` is stateless, `POST /meal-observations` carries no image fields, the `meal_images` table (schema.ts:324) is dead code, and the ADR 0013/0023 R2 pipeline was never built. Persisting images is therefore out of scope for this plan (noted as a follow-up).

## Goal 1 — Optional before-photo in measured mode (frontend-only, no backend changes)

The photo's job in measured mode is **identification, not measurement**: improve the dish name that feeds reference auto-matching, and cross-check the user's typed components against what's in the photo. Weights remain hard facts.

Changes in `frontend/src/components/LogMealModal.tsx` + `frontend/src/features/nutrition-estimation/`:

1. **Form step (measured branch)**: add an `ImageSlot` (before, optional) reusing the estimated-mode component; replace the "no photos needed" copy with promoted-optional copy ("Add a photo — helps match the dish to the nutrition reference; weights stay exact").
2. **New pure helper** `features/nutrition-estimation/photoCheck.ts`: `compareMeasuredToProposal(measured: EditableComponent[], proposal: VlmProposal)` returning per-component flags — VLM saw a component the user didn't enter; measured weight differs from VLM central by > 50%; plus a dish-name proposal. Pure function so it's unit-testable; no new backend contract.
3. **Photo-check step** between form and result (only when a before image is attached in measured mode):
   - Call the existing `mealObservationApi.interpret(menu_name, beforeImage.base64)`.
   - Show VLM dish name with a "Use" chip (adopts it as `menu_name`, which then feeds the auto-matcher on create).
   - Show the cross-check list from the helper as soft warnings (amber notice banner style, same as existing banners). Never blocks — any `failed`/`unavailable` outcome skips straight to create, per ADR 0017.
   - Skip the step entirely when no photo is attached (current behavior preserved).
4. **Create call unchanged**: measured weights, `portion_mode: "measured"`, no image fields on the payload.

## Goal 2 — Make the pending-meal UI discoverable (small)

In `NutritionPage.tsx`:
- Keep the pending card behavior, but make rows clearly clickable (cursor/chevron affordance) and add a count badge in the card header ("2 meals need review").
- Add an always-visible hint under the AI input ("Log meal with photo" area) pointing to the pending card when the list is non-empty — cheap fix for the "no UI?" confusion without a new route.

## Goal 3 — Verification

- Unit test for `compareMeasuredToProposal` (matched / extra-component / weight-mismatch / empty-proposal cases), following the existing frontend test setup if present; otherwise verify via the existing Playwright spec `frontend/e2e/meal-observation.spec.ts` with a new measured-mode-with-photo case (mocked interpret response).
- `bun run build` (tsc + vite) and `bun run lint` in `frontend/` must pass.

## Explicitly deferred

- Persisting images: full ADR 0013/0023 pipeline (proxy upload, EXIF strip, private R2, `meal_images` metadata, signed GETs) — separate piece of work requiring R2 credentials and infra decisions.
- Per-component reference selection (one reference per observation is a bigger modeling change than this UI task).
- Camera capture (`capture="environment"`) can ride along as a one-line attribute on the new ImageSlot.
