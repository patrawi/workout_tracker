## 3. เขียน ADR ใหม่ (ไฟล์ละ decision ตามแบบที่ project ทำอยู่)
| ADR | Decision |
|---|---|
| 0015 | เสนอ consumed fraction ราย component เมื่อมี after image; ไม่มี after ให้เลือกจาก all/¾/½/¼ (Q28) |
| 0016 | แยก input ขั้นต่ำตามโหมด: estimated = ชื่อเมนู+before image; measured = ชื่อเมนู+น้ำหนักชั่ง ≥1 component, ภาพ optional (Q29) |
| 0017 | VLM output = proposal มี confidence; field confidence ต่ำถูกซ่อนไม่แสดงกัน anchoring; output เสีย → manual entry; ไม่เคย block การบันทึก (Q30+Q31) |
| 0018 | ช่วงความไม่แน่นอนมาจากฝั่งมวลเท่านั้น (น้ำหนัก estimated, latent hints, ingredient evidence อ่อน); ค่าที่ชั่ง/ยืนยันแล้ว/per-100g reference เป็นจุด (Q32) |
| 0019 | constraint จัดลำดับแข็ง/อ่อน ผ่อน soft อย่างโปร่งใสพร้อม flag ห้าม clamp เงียบๆ ห้ามแต่งช่วง (Q33) |
| 0020 | reference matching 3 ระดับ: เด่นชัด auto / กำกวมให้เลือก / ไม่ผ่านเกณฑ์ → pending (Q35) |
| 0021 | defer Weekly Menu Prior ranking ออกจาก V1; รูปเมนูรายวัน = label_or_menu evidence (Q37, ต่อยอด ADR 0003) |
| 0022 | dual-write central values ลง nutrition_logs พร้อม provenance marker; ตารางใหม่เป็น source of truth; revision ที่ยืนยันแล้ว sync แถวที่ linked (Q38) |
| 0023 | รูปเดินผ่าน backend (auth + strip EXIF server-side), อ่านด้วย signed GET อายุสั้น, อัปโหลดล้มเหลวไม่ block และแนบทีหลังได้ (Q39) |
| 0024 | เกณฑ์ ablation แบบ composite + hard-fail (Q40) |
| 0025 | DeepSeek vision หลัง provider-neutral adapter เป็น V1 VLM baseline; interpreter ablation ใช้โมเดลเดียวกันทั้งสองบทบาท เพื่อ attribute ผลที่บทบาทตาม ADR 0010 (Q42) |

## 4. ร่าง design spec ย่อ (เก็บใน docs/)
รวม flow V1 ต่อโหมด, VLM contract fields, ตัวแปรคำนวณ + constraint priority, explanation fields, matching tiers, pending flow, dual-write, image path — พร้อมค่า default ชั่วคราวของตาราง latent-factor hints (เช่น น้ำมันชัด = 6–12% ของมวล component) ที่ mark ว่า provisional รอ calibration
- ส่วน VLM: ระบุว่าบทบาท VLM เป็น model-neutral ตาม contract Q30, V1 เลือก DeepSeek vision (รูปใส่ได้เฉพาะ user message, ใช้ JSON output mode, จ่ายรูปเป็น token ~≤1024 token/รูป)
